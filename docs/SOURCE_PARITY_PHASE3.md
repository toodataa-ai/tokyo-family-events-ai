# 第三弾：26固定サイトの取得・掲載照合進捗

対象: site/data/discovery_sources.json の有効な固定ソース26件。
既存のレガシー18サイトを削除・無効化せず保持する。第一弾・第二弾の監査対象も含めて表示する。

## 状態を混同しないルール
- URL取得: 登録URLを実際に確認した状態。月別URLは対象6週に含まれる各月で確認する。1URLでも取得できない場合は partial_error / source_error のまま保持する。
- 参考リンク: HTMLにイベント関連の語が含まれるURLの観測数。ナビゲーションや関連企画を含み得るため、イベント総数でも掲載漏れ確定数でもない。
- 候補ID・開催日・採否・公式根拠・本番掲載照合: このURL取得監査だけでは未検証。候補数・掲載数・除外数・重複数・未照合数は null にする。0にしない。
- 第一弾・第二弾の専用アダプターが存在するサイトは監査種別だけ表示し、専用監査で個別照合が済んだかは別の監査ジョブの結果で判定する。

## 表示と運用
- site/source-audit.html に固定ソースの最終確認日時・対象期間・登録ページの取得成功/一部失敗/失敗、参考リンク件数、個別照合状態、根拠URLを表示する。
- トップページからリンクできる。画面は全件/状態別/名称検索に対応し、読み取りに失敗した場合は監査未実施と表示する。
- DOM textContentで安全に生成。サイト本体のカード、星、Canva、検索、画像、採否に影響を与えない。
- Actionsで26サイトのソースアクセス状況を検査し、専用の site/audit/fixed_sources.json にのみ実行結果を保存する。
- このJSONの更新は監査専用であり、data-production、site/data、既存イベント・採否記録・更新履歴を変更しない。
- GitHub Actionsは必須ソースに失敗があれば失敗として残す。他の安全なデータ更新・公開がそれだけで止まらないよう独立ジョブとする。
- 本番アプリは承認前に変更しない。mainのプレビューで非破壊検証する。

## 未完了の範囲
第三弾では全ソースのアクセス状態を可視化する。全26の個別候補を日時・会場まで抽出して完全な掲載漏れ監査とするには、
ソースごとに日付行・詳細ページ・ページ送りを読む専用アダプターを追加する必要がある。
一部サイトだけ対応しても全件を網羅したとは言わない。取得不能・未検証は未解決として残す。
