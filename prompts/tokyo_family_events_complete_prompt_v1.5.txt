東京23区 子連れイベント AI探索・完全版プロンプト v1.5
【探索ソース統合＋子連れ適性8軸評価＋判断根拠監査版】

【この文書の位置づけ】
このファイルは東京23区の子連れイベントを6週間ローリングで探索し、候補の発見力を高めながら、掲載・除外の判断根拠を候補単位で保存し、後から評価ロジック自体を改善できるようにする正本プロンプトである。

競馬予想と同じく、作業開始時にファイル名順から最新版を推測してはならない。必ず `site/data/latest_prompt.json` を最初に読み、その `version` と `path` を解決し、そこが指すプロンプトだけを正本として使う。

最新版ポインタ、履歴、指示先ファイルのいずれかが不整合なら作業を続行しない。

────────────────────
0. 実行開始時の必須処理
────────────────────
1. `site/data/latest_prompt.json` を取得し version/path を解決する。
2. `site/data/prompt_history.json` に同一version/pathがあることを確認する。
3. `site/data/family_fit_rubric.json` を読み、子連れ適性評価の正本とする。
4. `site/data/discovery_sources.json` を読み、公式系ソースとレガシー由来イベント媒体を探索対象に含める。
5. 各対象週run manifestに prompt.version/path/pointer/resolved=true を保存する。
6. 最新版解決前に探索を始めてはならない。

────────────────────
1. 6週間ローリング対象
────────────────────
horizon_index=1〜6を持つ。
- 1〜2: publication_tier=full。全掲載イベント verified 必須。画像70%以上。
- 3〜4: publication_tier=preview。verified/announced を許容。
- 5〜6: publication_tier=announcement。イベント名・日付・会場を公式確認できたものを早期掲載。

週が近づくたびに前回データを再探索・再監査し、announced→verifiedへの昇格、中止・延期・変更を反映する。

────────────────────
2. PHASE A: 発見ソースを統合して23区探索
────────────────────
23区を必ず1区ずつ独立して探索する。

探索レイヤー:
A. 各区公式: イベント、観光、子育て、文化、公園、図書館、児童館等
B. 東京都・都立施設・公的施設
C. 主催者・会場・商業施設・鉄道・交通・スポーツ・劇場・大学等の公式
D. `discovery_sources.json` のイベント媒体。特に旧Pythonシステムが参照していたポータル群を候補発見用として必ず確認する
E. その他の子育て・地域イベント媒体
F. Web横断検索

重要原則:
- イベント媒体は「発見用」。媒体に載っているだけで掲載確定しない。
- 最終確定は可能な限り自治体・公的施設・主催者・会場公式で行う。
- レガシーPythonの出力JSONを正本にはしない。レガシーが参照する情報源そのものを探索対象として使う。
- 「子ども向け」と明記されたイベントだけに限定しない。祭り、花火、鉄道、動物、科学、防災、スポーツ、食、展示等も家族価値を評価する。

最低検索語:
子ども/子供/親子、イベント、祭り/フェス、ワークショップ/体験、無料、スタンプラリー、鉄道/電車、動物、科学、防災/消防。

coverage.wards[]に status, queries, sources_checked, candidate_count, published_count, note を残す。「見つからない」と「探していない」を混同しない。

────────────────────
3. PHASE B: 候補プール固定・重複排除
────────────────────
発見した候補を、掲載判断の前に候補プールとして固定する。
最低項目: candidate_id, ward, name, discovery_url, official_url, source, date_start/date_end, venue, discovery_sources[]。

重複判定は canonical official_url、正規化イベント名、開催日、会場を併用する。同一イベントを媒体違いで発見した場合は1候補へ統合し、どのソースで発見したかは discovery_sources[] に残す。

重複として落とした候補もdecision auditから捨てない。decision=`duplicate` とし、duplicate_of と理由を保存する。

────────────────────
4. PHASE C: 子連れ適性8軸評価
────────────────────
正本は `site/data/family_fit_rubric.json`。
各候補を次の8軸で独立評価する。
1. child_target: 子ども対象度
2. interactivity: 体験性
3. age_fit: 幼児・小学生への年齢適合
4. stay_flexibility: 滞在自由度
5. burden: 安全・身体・時間・混雑等の負担
6. cost: 家族利用時の費用負担
7. reservation: 予約難易度・参加可能性
8. family_value: 家族でわざわざ行く価値

各軸は A/B/C/D/unknown と、必ず具体的なreasonを持つ。unknownを推測で埋めない。

総合評価 overall もA/B/C/D/unknownを付ける。ただし総合評価だけで掲載・除外を自動決定してはならない。

【Hard exclusion】
以下は原則即除外し、hard_exclusionコードと根拠を残す。
- adult_only: 成人限定・成人向けが明示
- minors_prohibited: 未成年/子ども入場不可
- safety_unsuitable: 子ども同伴に明確に不適切な危険条件
- outside_23wards: 東京23区外
- date_mismatch: 対象週末と重ならない
- no_official_basis: full時点で開催根拠を確認できない
- cancelled_or_postponed: 中止・対象週外への延期

【Soft evaluation】
次は自動除外しない。必ず8軸を見て家族価値とトレードオフを記録する。
- adult_oriented: 成人向け要素が強いが子ども禁止ではない
- child_program_absent: 子ども専用企画が確認できない
- passive_only: 観覧中心
- night_burden: 夜間
- crowd_burden: 大混雑が想定
- high_cost: 家族利用時に高額
- reservation_difficult: 予約必須・締切間近/終了
- age_mismatch: 主対象年齢とのズレ
- family_value_low: 家族のおでかけとして相対価値が低い

花火、大型祭り、イルミネーション、鉄道、夜間動物園等は子ども専用でなくても family_value が高ければ掲載可能。C/D評価の掲載も禁止しないが、override_reason に「注意点を上回る掲載価値」を明記する。

────────────────────
5. PHASE D: 掲載判断・decision audit固定
────────────────────
各候補に decision=`published|excluded|duplicate` を付ける。

published/excluded候補は最低限以下を保存する。
- candidate_id
- name / ward
- decision
- family_fit.rubric_version
- family_fit.axes 8軸
- family_fit.overall
- family_fit.score（任意。診断用であり自動排除には使わない）
- hard_exclusion（なければnull）
- exclusion_type=`hard|soft|null`
- primary_reason_code
- reason_codes[]
- reasons[]（人間が読める具体文）
- evidence[]（URLと、何を根拠にしたか）
- override_reason（C/D掲載時必須）

週ごとに decision audit JSON を作り、run.source_data.decision_file から参照する。

完全な新規runでは次を満たすこと。
`candidate_total = published + excluded + duplicate`
すべての候補に個票が存在し、除外理由を集計可能であること。

旧バージョンからの移行データで候補個票が保存されていない場合だけ migration_incomplete=true を許容する。過去の除外理由を後付けで推測してはならない。次回その週をv1.5で再探索した時点で完全監査へ置き換える。

────────────────────
6. PHASE E: 掲載イベント整形
────────────────────
掲載イベントは従来項目を維持する。
id, ward, name, url, official_url, source, image, period, date_start/date_end, time, venue, price, description, categories[], family_fit, reservation, indoor_outdoor, ai。

family_fitには可能な限りdecision auditと同じ8軸・overall・reasonを反映する。コピペ契約v1には評価メタデータを混ぜない。

────────────────────
7. PHASE F: サムネイル取得
────────────────────
優先順位: 公式og:image → twitter:image → itemprop/image_src → JSON-LD → 公式本文画像 → 情報元画像。
推測URL・data URLは禁止。fullは画像70%以上を公開ゲートとする。preview/announcementは努力義務。

────────────────────
8. PHASE G: 公式情報の全件再監査
────────────────────
掲載候補を1件ずつ公式再監査する。
優先: 自治体/東京都/公的施設 → 主催者/会場公式 → 公式観光協会 → 主催者提供情報を明記する提携媒体。

照合: name, date, time, venue, price, reservation/deadline, target, cancellation/weather, official_url。
field state: pass/corrected/unknown/not_applicable。
name/date/venueは必ずpass/corrected。
fullはstatus=verifiedのみ。preview/announcementはannounced可。unknownは推測しない。

公式監査で子どもの対象条件・料金・予約締切等が変わり8軸評価に影響する場合、decision auditも同じrun内で再評価する。

────────────────────
9. PHASE H: run manifest
────────────────────
標準stages:

2 discover_23_wards
3 normalize_and_dedupe
4 family_fit_decision_audit
5 freeze_candidates
6 enrich_images

summaryには wards_checked, candidates, published, excluded, duplicate_removed, verified, announced, corrected, thumbnail_count, thumbnail_coverage, decision_audit_complete を残す。

────────────────────
10. 公開前Validator
────────────────────
必須:
- prompt governance PASS
- `tools/validate_data.py --strict` PASS
- `tools/validate_decisions.py --strict` PASS
- npm test PASS

decision validatorは新規v1.5 runで次をFAILにする。
- decision_fileなし
- 候補総数とpublished/excluded/duplicateが不整合
- excludedに理由なし
- 8軸不足
- 各軸reason不足
- evidence URLなし
- hard exclusionコード不正
- C/Dをoverride_reasonなしでpublished

────────────────────
11. サイト可視化
────────────────────
サイトで次を確認できるようにする。
- 候補数 / 掲載数 / 除外数
- Hard除外 / Soft除外
- decision auditが完全か移行中か
- 掲載イベントの8軸評価（存在する場合）
- 除外候補のイベント名、主理由、理由全文、根拠URL
- 旧方式で理由個票がない場合は「旧方式のため個票なし」と明示

これにより「なぜ落ちたか」を人間が確認し、後日、評価軸・重み・閾値をブラッシュアップできる状態を維持する。

────────────────────
12. コピペ契約 v1
────────────────────
順番を絶対変更しない。
1 タイトル
2 場所
3 日時
4 料金
5 説明
6 公式サイト
7 情報元サイト
8 サムネイル画像URL（存在時のみ）

AI評価・verification・decision auditはコピー本文に含めない。

────────────────────
13. 禁止事項
────────────────────
- 最新版プロンプトをファイル名順で推測
- 候補を判断理由なしで捨てる
- C/Dという理由だけで機械的に除外
- 子ども専用企画がないという理由だけで大型家族イベントを除外
- unknownを推測で埋める
- 媒体情報だけでverifiedにする
- 過去の保存されていない除外理由を後付け生成
- コピペ契約v1の変更
